## 2026-11-10 - Account Takeover via Reset Token Exposure in API Responses
**Vulnerability:** The password recovery request endpoint (`/api/auth/reset` with `action: "request"`) returned `debugResetUrl: resetUrl` in the HTTP response JSON. An unauthenticated attacker requesting a reset for any user's email would receive the signed recovery token directly in the HTTP response body, enabling immediate account takeover.
**Learning:** During development or testing, developers sometimes return debug tokens or URLs in JSON payloads to simplify local testing before real email transport is configured. This directly violates the security boundary and defeats obfuscated response logic (e.g., generic success messages to avoid email enumeration).
**Prevention:** Never include authentication tokens, reset tokens, or URLs with embedded credentials in API responses. In local/development environments, log recovery URLs exclusively to server console output or require explicit non-production environment flags that are strictly disabled by default.
